# TC377 300 / 500 MHz DIY 配置与实板验证

2026-10-14开始验证，2026-10-15修订外设时钟。当前 TC37x 实板，原供电，未调核心电压。默认三核均为 500 MHz。
在 `Configurations/Ifx_Cfg.h` 将 `TC377_CPU_MHZ` 改为 300 后重新构建，即使用标准档。

2026-10-15整数候选测试后补正：500 MHz档PFlash ECC等待从RECC=3改为4。
数据手册tPFECC为10 ns，500 MHz需要5周期，寄存器写周期数减1，因此为4。
此前21分钟长测及其镜像哈希对应RECC=3的历史版本，不能作为本次RECC=4镜像的同一哈希证据。
本次候选失败记录及RECC=4恢复回归见[整数候选验证](TC377-整数候选验证.md)。
频率根据时钟寄存器与工程声明的 20 MHz 晶振计算，未用外部频率计测量。

2026-10-15外设性能修订：用户要求CPU保持500 MHz，GTM不低于200 MHz、STM不低于100 MHz，允许更高。
当前目标改为GTM333.333 MHz、STM/SPB/MCANH/GETH166.667 MHz；FSI仍166.667 MHz。
TIM0和TOM1使用的Cluster0/1显式取消默认二分频，CMU及TOM1 Cluster也为333.333 MHz。
PWM测试为覆盖1 kHz的16位计数范围继续使用/16时钟，即约20.833 MHz，并非降低GTM模块时钟。
新增`gtmCmuHz`、`gtmTom1Hz`、`pwmTickHz`读回量，避免仅查看GTM总线频率。
最新测试证据位于`doc/overclock500-fast/`；下方其它测试目录均保留其对应历史配置的数据。

2026-10-15补充：用户实际断电重上电暴露CAN消息RAM未初始化的ECC告警，
已在启用CAN节点前增加手册规定的MCR.RINIT初始化。修正版经过用户再次断电重上电，
自主运行500 MHz且CAN RAM ECC标志为0，详细证据见`doc/overclock500-coldboot/`。
修正版断电启动后173秒快照的功能错误、运行期SMU及37个SSH源状态全部为0，
COM10 1 MiB回传逐字节比较零错误。随后三核CPU及Safety看门狗四种停喂测试均自主
重启，重新通过三核PSPR MBIST，CAN及其它外设继续运行且告警为0。
看门狗脚本现要求复位后直接处于运行态；若停在调试入口则判定失败，不再调用run后记作自主恢复。

## 时钟树

| 时钟 | 300 档 MHz | 500 档 MHz |
|---|---:|---:|
| CPU0 / CPU1 / CPU2 / SRI | 300 | 500 |
| SPB / MCANH | 100 | 166.667 |
| STM | 100 | 166.667 |
| BBB | 150 | 250 |
| FSI | 100 | 166.667 |
| FSI2 | 300 | 500 |
| GTM | 200 | 333.333 |
| GETH 时钟 | 150 | 166.667 |
| Peripheral PLL1 / PLL2 | 320 / 200 | 320 / 200 |
| QSPI 源 / 屏幕 SPI | 200 / 50 | 200 / 50 |
| ASCLINS / ASCLINF | 80 / 200 | 80 / 200 |
| MCAN / I2C / ADC 源 | 80 / 100 / 160 | 80 / 100 / 160 |

500 档系统 PLL：PDIV=0、NDIV=49、K2DIV=1，20×50/2=500 MHz。
先以 /8 启动，再经 /4、/3、/2 升频，每步等待 1 ms。
升频前整字写 Flash 等待配置，保留其它字段：PFlash RFLASH=15、RECC=4；
DFlash RFLASH=24、RECC=4。300 档分别为 8/2 与 9/1。

分频满足手册的时钟比例要求，包括 SRI/BBB=2、GTM/SPB=2、MCANH=SPB。
此前 CAN 初始化失败已通过令 MCANH 与 SPB 相等解决。
CPU 随 SRI 超频，FSI2 的 /2、/3 分频值为保留值，不能靠它们隔离超频。
**当前500档的CPU、SRI、FSI、FSI2、BBB、SPB、MCANH、STM、GTM超出数据手册额定上限。**
比例正确不意味着频率额定，也不意味着可取得与 300 MHz 相同的可靠性保证。

## 接线和并发测试

- P20.3 TOM1 CH12 输出 → P20.0 TIM0 CH6 捕获；1/10/100 kHz ×25/50/75%，九组循环，周期及高电平长度允许 ±3 tick。
- P14.0 TX / P14.1 RX 接下载器串口 COM10，115200 8N1；电脑发送 1 MiB 随机二进制，每块256字节，逐字节比较回传。
- IPS200 使用 QSPI2、DMA0/1，命令与像素均50 MHz，每秒整批刷图；DMA 每请求一帧，解决并发负载下原双帧请求队列停顿。
- 三核同时执行256步整数递推、浮点计算、各核栈上的1 KiB RAM写入与反码校验。
- 三核六方向邮箱传递16words，核间GPSR中断通知，验证序号、数据、校验和、应答；非缓存DLMU地址保证共享一致性，原子锁检查计数与反码。
- STM0 1ms中断；CCU60 T12 100Hz与STM比较；GPT12 T3每秒与STM比较。
- DMA2每秒搬运256字节并校验；FCE CRC32与独立软件多项式实现比较。
- CAN0 node0/node1片内虚拟总线，双向经典8字节、CAN FD 64字节，500k/2M；四类帧分别计数。
- CAN模块使能后、节点启用前执行MCR.CCCE/CI、RINIT翻转、dummy read、RBUSY等待及退出流程，初始化全部消息RAM及其ECC。
- SMU software alarm0每秒触发IRQ并清除；三核CPU WDT和Safety WDT持续启用，Safety仅在三核计算均有进展时喂狗。
- 上电测试三核PSPR的MBIST，测试期间关闭程序缓存并等待三核屏障；完整DSPR、全部SRAM、LBIST均未测试。
- DTS记录芯片温度，未独立校准。

计数快照读取期间程序保持运行，因此不同变量并非同一瞬间采集。
PWM、STM、CCU6、GPT12的内部比较不能替代示波器/频率计对绝对频率和信号质量的测量。
中断次数允许通知合并，不要求与邮箱包数相等。

## 安全诊断与复位

启动保留 `bootAlarms` 和 `sshBoot`，随后清源标志再清SMU状态，观察运行期新增状态。
SSH源的FAULTSTS受Safety ENDINIT保护，使用16位写；不关闭ECC检测或报警通知。
MC40的FSI RAM启动告警按TC37x勘误SMU_TC.H012处理，仅清源标志，不读写FSI RAM内容。
三核PSPR MBIST均通过，`mbistStatus`与错误地址为0；MBIST操作本身的OPERR在测试结束后清除。

CPU0/1/2、Safety分别停止喂狗，检查看门狗复位原因和自主恢复。
此前测试存在调试器介入后的恢复证据；本次修正启动阶段WDT再次超时的问题，
在PLL等待前禁用CPU0和Safety启动WDT，初始化完成后重新配置并启用运行期WDT。
DAS重连会暂停WDT，因此测试主循环每毫秒检查OCDS状态，恢复运行期计时。
最终试验以SMU复位位、对应AD8超时位、faultCommand清零、三核MBIST及计算恢复为依据。
RSTCON.SMU选择系统复位，避免应用复位后PSPR测试影响其它核心上下文。

**ALM7[31]已通过降低FSI时钟消除，未关闭或屏蔽报警。**
对照证据：300 MHz使用与500档相同的较长Flash等待周期时告警为0；
CPU500、SPB/GTM/MCANH83.333 MHz等配置不变，仅FSIDIV=2时（FSI250 MHz）
ALM7[31]出现，FSIDIV=3时（FSI166.667 MHz）消失。公开资料不足以判断芯片内部的
具体故障节点，实测将软件触发条件收敛到FSI分频。没有用其它型号的FLASH_TC.051解释该现象。
当前时钟树同时满足SRI/FSI=3、FSI2/FSI=3、FSI/(SPB/2)=2、GTM/SPB=2。
GTMDIV=1时GTM源为2×SPB，并非简单的PLL/GTMDIV；此前低SPB档的GTM倍频关系不能照搬。

ADC按用户要求未测试。未连接的外部CAN收发器、I2C设备、Ethernet PHY、其它SPI设备未验证；
HSM、密码学、MPU故障注入、锁步故障注入、全存储器ECC错误注入、FSP输出未测试。
现有固件是持续测试程序，后续应用需保留时钟配置并按实际任务重新验证。

## 结果与复现

同一代码的300 MHz档也已实际烧录回归：235秒快照功能错误、SMU/SSH运行期状态均为0，
三核PSPR MBIST通过，1 MiB串口逐字节比较零错误；GTM/CMU/TOM1均200 MHz，STM/SPB100 MHz。
该档证据为同目录`baseline300.json`及`uart-baseline300.json`。
最后已恢复默认500 MHz，ELF/HEX SHA256均与上述持续测试镜像完全一致；恢复后主频、外设频率及运行期状态再次核对通过。
恢复记录为`restored500.json`、`restored-sha256.json`和`restored-flash.txt`，板子保留500 MHz运行。
