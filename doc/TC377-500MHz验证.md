# TC377 300 / 500 MHz DIY 配置与实板验证

2026-10-14，当前 TC37x 实板，原供电，未调核心电压。默认三核均为 500 MHz。
在 `Configurations/Ifx_Cfg.h` 将 `TC377_CPU_MHZ` 改为 300 后重新构建，即使用标准档。
频率根据时钟寄存器与工程声明的 20 MHz 晶振计算，未用外部频率计测量。

## 时钟树

| 时钟 | 300 档 MHz | 500 档 MHz |
|---|---:|---:|
| CPU0 / CPU1 / CPU2 / SRI | 300 | 500 |
| SPB / MCANH | 100 | 125 |
| STM | 100 | 62.5 |
| BBB | 150 | 250 |
| FSI | 100 | 250 |
| FSI2 | 300 | 500 |
| GTM | 200 | 125 |
| GETH 时钟 | 150 | 125 |
| Peripheral PLL1 / PLL2 | 320 / 200 | 320 / 200 |
| QSPI 源 / 屏幕 SPI | 200 / 50 | 200 / 50 |
| ASCLINS / ASCLINF | 80 / 200 | 80 / 200 |
| MCAN / I2C / ADC 源 | 80 / 100 / 160 | 80 / 100 / 160 |

500 档系统 PLL：PDIV=0、NDIV=49、K2DIV=1，20×50/2=500 MHz。
先以 /8 启动，再经 /4、/3、/2 升频，每步等待 1 ms。
升频前整字写 Flash 等待配置，保留其它字段：PFlash RFLASH=15、RECC=3；
DFlash RFLASH=24、RECC=4。300 档分别为 8/2 与 9/1。

分频满足手册的时钟比例要求，包括 SRI/BBB=2、GTM/SPB=1、MCANH=SPB。
此前 CAN 初始化失败已通过令 MCANH 与 SPB 相等解决。
CPU 随 SRI 超频，FSI2 的 /2、/3 分频值为保留值，不能靠它们隔离超频。
**500 档的 CPU、SRI、FSI、FSI2、BBB、SPB 超出数据手册额定上限。**
比例正确不意味着频率额定，也不意味着可取得与 300 MHz 相同的可靠性保证。

## 接线和并发测试

- P20.3 TOM1 CH12 输出 → P20.0 TIM0 CH6 捕获；1/10/100 kHz ×25/50/75%，九组循环，周期及高电平长度允许 ±3 tick。
- P14.0 TX / P14.1 RX 接下载器串口 COM10，115200 8N1；电脑发送 1 MiB 随机二进制，每块256字节，逐字节比较回传。
- IPS200 使用 QSPI2、DMA0/1，命令与像素均50 MHz，每秒整批刷图；DMA 每请求一帧，解决并发负载下原双帧请求队列停顿。
- 三核同时执行256步整数递推、浮点计算、各核栈上的1 KiB RAM写入与反码校验。
- 三核六方向邮箱传递16words，核间GPSR中断通知，验证序号、数据、校验和、应答；非缓存DLMU地址保证共享一致性，原子锁检查计数与反码。
- STM0 1ms中断；CCU60 T12 100Hz与STM比较；GPT12 T3每秒与STM比较。
- DMA2每秒搬运256字节并校验；FCE CRC32与独立软件多项式实现比较。
- CAN0 node0/node1片内虚拟总线，双向经典8字节、CAN FD 64字节，500k/2M；四类帧分别计数。
- SMU software alarm0每秒触发IRQ并清除；三核CPU WDT和Safety WDT持续启用，Safety仅在三核计算均有进展时喂狗。
- 上电测试三核PSPR的MBIST，测试期间关闭程序缓存并等待三核屏障；完整DSPR、全部SRAM、LBIST均未测试。
- DTS记录芯片温度，未独立校准。

计数快照读取期间程序保持运行，因此不同变量并非同一瞬间采集。
PWM、STM、CCU6、GPT12的内部比较不能替代示波器/频率计对绝对频率和信号质量的测量。
中断次数允许通知合并，不要求与邮箱包数相等。

## 安全诊断与复位

启动保留 `bootAlarms` 和 `sshBoot`，随后清源标志再清SMU状态，观察运行期新增状态。
SSH源的FAULTSTS受Safety ENDINIT保护，使用16位写；不关闭ECC检测或报警通知。
MC40的FSI RAM启动告警按TC37x勘误SMU_TC.H012处理，仅清源标志，不读写FSI RAM内容。
三核PSPR MBIST均通过，`mbistStatus`与错误地址为0；MBIST操作本身的OPERR在测试结束后清除。

CPU0/1/2、Safety分别停止喂狗，均观察到复位并恢复。
CPU0一次捕获到RSTSTAT的SMU复位位和AD8的CPU0超时位。
其它试验DAS重连后会停在A0000000，部分复位诊断被调试复位覆盖，不能声称都捕获到SMU原因。
继续执行后每种试验均重新通过3核PSPR MBIST、恢复计算和通信，faultCommand清零。
RSTCON.SMU选择系统复位，避免应用复位后PSPR测试影响其它核心上下文。

**仍未解决：500 MHz下ALM7[31] Flash Stored Configuration Error持续存在。**
相同测试代码300 MHz对照没有此标志。不能把它归类为无害告警，也不能宣称安全诊断全部通过。
目前功能校验未见对应数据错误；不能据此排除潜在Flash配置问题。
其它型号的FLASH_TC.051不能直接套用到TC37x，本报告没有用该勘误解释此告警。

ADC按用户要求未测试。未连接的外部CAN收发器、I2C设备、Ethernet PHY、其它SPI设备未验证；
HSM、密码学、MPU故障注入、锁步故障注入、全存储器ECC错误注入、FSP输出未测试。
现有固件是持续测试程序，后续应用需保留时钟配置并按实际任务重新验证。

## 结果与复现

最终镜像连续运行 **1237 秒（20分37秒）**，28次运行中快照均显示三核计算、
IPC、PWM九组、STM周期超限、CCU6、GPT12、DMA、CRC、CAN及串口错误为0，
37个SSH源的运行期累计状态为0。唯一持续SMU标志为ALM7[31]。

| 项目 | 最终快照 |
|---|---:|
| 三核计算轮数 CPU0 / CPU1 / CPU2 | 39,865,189 / 42,511,801 / 42,511,510 |
| 三核邮箱接收累计 | 231,361,727 |
| PWM九组有效快照累计 | 17,153,141 |
| STM中断 / 最大到达延迟 | 1,237,955 / 13.072 μs |
| CCU6中断 / GPT12检查 | 123,795 / 1,237 |
| DMA / CRC检查 | 各1,238 |
| CAN四类帧 | 每类1,238，共4,952 |
| 完成整批屏幕刷新 | 1,237 |
| SMU软件告警中断 | 1,237 |
| 峰值DTS温度 | 55.8307°C |
| COM10随机二进制回传 | 5 MiB，五轮均逐字节比较零错误 |

300档在MC40修正后的55秒快照全部功能错误、SMU状态均为0；此前156秒
功能对照也无错误，300档1 MiB串口回传零错误。两档均有三核PSPR MBIST通过证据。
看门狗四种复位试验发生在增加MC40清源处理前，使用相同的500档时钟树与看门狗逻辑。
未进行断电冷启动、温度箱或供电变化测试；该结果只覆盖本次供电与负载。

实测快照、UART结果和看门狗恢复证据位于 `doc/overclock500/`。
最终连续运行时间、各项计数和温度以 `final500.json` 为准，300对照以 `baseline300.json` 为准。
`tools/overclock/` 保存本机DAS读取工具源码与串口脚本；工具依赖Windows、PowerShell 7、DAS64和工程的TriCore GCC。
先将MCD源码编译为 `Debug/overclock-mcd.exe`；快照脚本按当前ELF解析符号地址，**ELF必须匹配烧录镜像**。
构建：配置ACS的TriCore GCC及tools到PATH后执行 `make -C Debug -j8 all`。
烧录保留 `-ucb off`；不改UCB/BMHD。Flasher校验完成后可能需要MCD `run`继续执行。
默认仅有300/500两档，不保留520为运行档。
原520试验文档保留为历史记录。
