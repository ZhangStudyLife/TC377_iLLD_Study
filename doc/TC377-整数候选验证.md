# TC377 CPU500 整数候选验证

2026-10-15。用户要求实际烧录并测试整数候选。

## 实际候选配置

| 项目 | MHz |
|---|---:|
| CPU0/1/2、SRI | 500 |
| SPB、MCANH | 125 |
| STM、GTM、CMU输入、TOM1 Cluster、GETH、BBB | 250 |
| FSI、FSI2 | 500 |
| TIM/TOM应用计数时钟 | 50 |
| PLL1、PLL2 | 320、200 |
| QSPI源、屏幕SPI | 200、50 |

SYS PLL保持DCO1000/K2除2。SPBDIV/MCANHDIV=4，STM/GTM/GETH/BBB为2，FSIDIV=1、FSI2DIV=1。
Cluster0/1不二分频；CMU_CLK0为GCLK/5，FXCLK选择CMU_CLK0为输入，TOM使用FXCLK0，TIM使用CLK0。
1/10/100 kHz周期分别为50000/5000/500，25/50/75%占空比也为整数计数，均在TOM16位范围内。
P20.3到P20.0为PWM回环，P14.0/P14.1通过COM10做115200 8N1回传。

## 216秒实板结果：候选未通过

烧录校验成功并进入主循环，CPU及全部上述时钟读回正确。三核PSPR MBIST通过。
运行到216秒，三核计算、六方向IPC、九组PWM、STM、CCU6、GPT12、DMA、FCE CRC、
CAN/CAN FD片内双向通信、屏幕QSPI/DMA及UART功能错误计数均为0，SSH运行期状态为0。
CAN四类帧均完成216帧；PWM九组均有有效样本；COM10 1 MiB逐字节比较零错误。
峰值DTS为63.9586°C。

但运行期`alarmSeen[7]=0x80000000`，即Flash Stored Configuration Error（ALM7[31]）。
启动后13秒、80秒、127秒及216秒均保留该累计标志。
启动会清除SMU历史状态后再观察运行期，因此不能将该结果解释为全告警为零。
本轮没有继续将该候选作为长测或冷启动通过的镜像。

保留SPB125、STM/GTM/GETH250及50 MHz应用计数，只将FSI降到250并设置对应DFlash等待，
PFlash仍使用修正后的RECC4作对照。46秒时功能错误仍为0，但ALM7[31]再次出现。
因此这项PFlash等待修正没有消除FSI250配置下的告警。

GETH仅核对时钟，未连接条件做收发验证；CAN是片内回环；ADC按用户要求未测。

## 补查发现的等待周期限制

本次发现此前整数候选分析漏算DFlash ECC等待字段上限；这是候选可用性的重要限制。

手册Part1表144规定，DFlash ECC周期至少为ceil(tDFECC×fFSI)，HF_DWAIT.RECC写周期数减1。
TC377数据手册tDFECC=20 ns；FSI500 MHz需要10周期，RECC应为9。
但该字段只有3位，最大7，即8周期、16 ns，无法按此配置覆盖手册的最坏情况延迟。
本轮使用字段最大值7，RFLASH49提供100 ns读取等待，实际DWAIT读回0x00070031。
这不等于满足完整DFlash最坏情况时序；本轮也没有进行DFlash编程或有效ECC读取测试。
不应将“其它功能测试没有计数错误”作为DFlash可靠性通过的依据。

同时补查PFlash：tPFECC=10 ns，fSRI500 MHz需要5周期，所以HF_PWAIT.RECC应为4。
原500档RECC3只提供8 ns。本次候选及恢复版本均已使用4；PWAIT读回0x0716040F。
300档RECC2本来即为10 ns，不需要修改。

## 最终保留版本

已撤回整数候选的分频和PWM修改，恢复CPU500、SPB/STM/MCANH/GETH166.667、GTM/CMU/Cluster333.333 MHz。
源码仅保留500 MHz分支的TC377_FLASH_RECC由3改4；原DFlash24/4在FSI166.667下仍满足上述等待下限。
没有保留候选运行档，没有修改UCB/BMHD或禁用ECC/报警。

恢复镜像重新构建并烧录校验，PWAIT与DWAIT实际读回分别为0x0716040F和0x00040018。
CPU0、CPU1、CPU2和Safety四种停喂均无需调试器run介入自主复位恢复，
RSTSTAT/bootReset包含SMU复位原因，AD8包含各自超时诊断位，faultCommand清零、三核MBIST重新通过，错误和运行期告警为0。

此前21分钟验证属于RECC3历史镜像；本次新镜像有独立哈希和回归记录，位于`integer-candidate/`。

本次RECC4恢复镜像在最后一次看门狗复位后运行167秒，功能错误、运行期SMU及SSH累计标志均为0，
三核PSPR MBIST通过，PWM九档均有有效样本，CAN四类各167帧。
COM10再次完成1 MiB随机回传，逐字节比较零错误，耗时131.438秒；板上UART计数同为1048576字节。
该次快照DTS及累计峰值64.8913°C。它是短时回归，没有替代此前历史镜像的21分钟长测，也没有做新镜像冷启动验证。

`candidate.patch`相对本轮起点9582b2b保存实际候选配置及PWM改动，仅供重现失败试验；不属于默认编译输入。
`final.json`、`fsi250-final.json`分别是216秒和46秒候选记录；
`restored-final.json`、`restored-uart.json`、`restored-wdt-*.json/.txt`属于最终RECC4镜像。
