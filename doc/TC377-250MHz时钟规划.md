# TC377 CPU500 / 250 MHz 时钟规划与短时试验

最新连续实板调试已完成，结论见[250 MHz实板调试结论](TC377-250MHz实板调试结论.md)：当前供电条件下，SPB250存在可重复的固定寄存器读取错误，未保留该运行档。

2026-10-15。用户要求CPU实际主频仍为500 MHz，优先采用整数MHz及简单倍数关系。
本次未保留新的运行档：试验后已恢复0ec8f15对应的500 MHz已验证镜像，ELF/HEX哈希完全匹配。

## 建议目标

| 时钟域 | 目标MHz | 配置关系 |
|---|---:|---|
| CPU0/1/2、SRI | 500 | 保持当前系统PLL与CPU直通 |
| SPB、MCANH | 250 | SPBDIV=2，MCANHDIV=2 |
| STM | 250 | STMDIV=2，1 tick=4 ns |
| GETH | 250 | GETHDIV=2；收发功能另需外部条件验证 |
| BBB | 250 | BBBDIV=2，保持当前值 |
| FSI | 250 | FSIDIV=2，存在既往及本次ALM7[31]记录 |
| FSI2 | 500 | 保持当前值 |
| GTM、Cluster0/1输入 | 250 | GTMDIV=2，Cluster不再二分频 |
| QSPI源 / 屏幕SPI | 200 / 50 | 保持当前值 |
| PLL1 / PLL2 | 320 / 200 | 保持当前值 |
| ASCLINS / ASCLINF / MCAN | 80 / 200 / 80 | 保持当前值 |

该目标满足手册列出的比例：SRI/SPB=2，MCANH=SPB，SRI/BBB=2，SRI/FSI=2，
FSI/(SPB/2)=2，GTM/SPB=1，SPB/STM=1。满足比例不代表当前板已通过这些超额定频率。

SPB250时不能继续保留FSI166.667：FSI/(SPB/2)=4/3，不满足整数比例。
GTM先选250 MHz，已达到用户原先不低于200 MHz的要求；GTM500 MHz在比例上也可成立，
但应在250目标完整通过后再单独评估。GTM350/400 MHz与固定SRI500的比例限制不兼容。

## 开发时使用的计数时钟

如果上述目标通过，建议CMU_CLK0=50 MHz（GTM250整数/5），TIM与TOM统一使用该时钟。
TOM FXCLK可选择CMU_CLK0为源并使用FXCLK0；不继续使用默认GCLK/16。
这样1/10/100 kHz的周期分别为50000/5000/500，25/50/75%占空比也均为整数计数，
并且均落在TOM的16位计数范围内。50 MHz计数时钟对应20 ns分辨率。
此项为后续规划，本次未修改PWM实现，也未声称完成该50 MHz计数配置的实板验证。

## 本次实板结果

1. CPU/SRI500，SPB/MCANH/STM/GETH/GTM/FSI均250，BBB250、FSI2为500：
   烧录校验成功，但启动停在`IfxCpu_Trap_busError`的debug指令，PC=0x8000790A。
   Trap Class4/TIN3，CPU0_DATR=0x8（Store Bus Error），DEADD=0xF00362A8，
   即Safety WDT控制寄存器；陷阱返回地址0x80004872位于时钟初始化期间的Safety ENDINIT操作。
   未进入主循环，未初始化的RAM计数没有测试意义，不将这些数值当作功能错误统计。
2. 仅将SPB/MCANH降到125，其余上述时钟不变：
   主循环运行，63秒快照CPU500、STM/GTM/GETH/FSI250均读回，功能错误计数及SSH运行期状态为0，
   但`alarmSeen[7]=0x80000000`，ALM7[31]持续存在。这与此前FSI250记录一致。
   该对照不能视为全250目标通过，也不能证明GETH收发功能正常。
3. 已恢复此前CPU500/SPB166.667/STM166.667/GTM333.333配置：
   运行态、三核PSPR MBIST及运行期错误/告警重新核对通过，镜像哈希与原持续测试镜像一致。

原始证据在`clock250-evaluation/`。`startup-clocks.txt`保留调试器的原始读数，
启动陷阱状态下并非所有外设读数都可独立验证，不用它们推断所有时钟已成功运行。
本次没有断电冷启动确认，没有对250目标进行长时间运行测试。
ADC继续按用户要求跳过。

## 后续调通顺序

先定位SPB250启动期间Safety WDT总线错误，检查ENDINIT访问及升频切换过程；
再定位FSI250对应ALM7[31]，在保留诊断功能的条件下处理原因。
这两项通过后，再实施50 MHz应用计数时钟，复测PWM、三核/IPC、定时器、DMA/CRC、
CAN/CAN FD片内通信、串口、屏幕及四种看门狗恢复，最后做用户断电上电和持续联合测试。
目前没有证据保证这块板子最终可以完成全250目标；日常开发仍使用已验证配置。

依据：本地TC3xx用户手册Part1表280的CCU比例、CCUCON0/5描述及GTM CMU说明，
以及仓库iLLD的IfxGtm_Cmu_getFxClkFrequency、IfxGtm_Tom_Pwm_Config实现。
